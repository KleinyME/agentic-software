# Project Steward Skill Suite

This Codex skill suite routes creative, product, technical, data, hardware, and release work without making one professional role the temperament of every task.

Use `project-steward` as the neutral lead for mixed or ambiguous projects. It selects the current work stage, primary craft, freedom zone, protected invariants, and only the risk overlays that actually apply.

This v0.13 package also contains an intention-first Agentic Software Harness for active software delivery. After `project-steward` assigns technical implementation as the primary craft, `software-steward` coordinates situation classification, safe automation discovery, conditional exponential strategy, architecture, fresh-context agent graphs, assembly, independent assurance, memory, copy and audience boundaries, security, verification, and release.

Key roles:

- `creative-director`: blank-page invention, brand, marketing, copy, visual and industrial design, campaigns, interfaces, and instrument appearance.
- `design-distinctiveness`: evidence-backed business specificity, customer-job page structure, typography, and cross-concept sameness review.
- `software-steward`: implementation, architecture, data identity, concurrency, integrations, runtime behavior, tests, and technical hardening.
- `project-memory-steward`: progressive lane-scoped memory, technical evidence, and explicit provisional/approved/rejected/superseded decision authority.
- `release-steward`: production promotion and live verification after the result is accepted.

The suite also includes focused brand, visual, copy, frontend-memory, security, environment, no-theater, lean architecture, senior architecture, and repo-foundation specialists. For evidence-grounded client-facing redesigns and concept batches, `design-distinctiveness` runs after positioning and before visual/frontend execution. Load specialists only when the routed work needs them.

Use `graph-engineering` when the shape of work or knowledge is the problem: multi-agent fan-out/fan-in, conditional routing, independent verification, durable execution state, knowledge graphs, GraphRAG, or temporal project memory. It keeps sequential work in one loop, separates task graphs from knowledge graphs, requires typed edges and explicit state ownership, and places human gates only where mistakes are expensive to undo.

Use `workflow-automation-architect` to notice worthwhile automation during any software build, even when the user did not explicitly ask. It asks about missing business intent only when the answer changes the architecture, distinguishes deterministic automation from model/agent judgment, invokes graph engineering only for graph-shaped work, and exports deduplicated opportunities to OB1/OpenBrain or Hermes's approval-based suggestions without silently creating jobs.

The suite expands initiative without silently expanding authority. Each proactive workflow declares whether it may only observe, suggest, draft, execute a reversible pre-approved action, or prepare a consequential action for a named gate. Wider context and stronger models never grant broader execution permission by themselves.

The optional **Weirdo Pass** is formally a `non_obvious_option` stage: after intent and a credible baseline exist, it challenges one limiting assumption and proposes one causal, falsifiable alternative. The **Toby pattern** is a read-only workflow-friction observer: it turns repeated corrections, retries, escalations, context gaps, and handoff delays into source-backed records, eval cases, and reviewed improvement proposals. Neither pattern creates a standing agent, graph, or self-modifying system by default, and their operator nicknames are not public UI copy unless the approved product voice says otherwise.

The Weirdo now has a bounded cognitive personality rather than a theatrical persona: mischievously curious, cross-disciplinary, willing to invert or subtract inherited assumptions, ambitious about outcomes, and conservative about authority. It must show the strange conceptual leap, causal mechanism, reversible test, and stop rule. The weirdness belongs in the idea, not forced jokes or customer-facing copy.

The underlying Agentic Software Harness has five layers: constitution and intent; situation compilation and capability selection; bounded execution; assurance and release; and observed, versioned learning. A task-specific capability packet is an ephemeral routing decision, not a generated mega-prompt. Safety and assurance overlays cannot be removed to save context.

For meaningful multi-domain work, selected skills become node contracts for separate fresh-context agents. The root harness owns the dispatch graph, budgets, context exclusions, write scopes, and one accountable assembler. Agents return typed artifacts or findings; assembly resolves conflicts rather than concatenating or voting; a separate fresh-context assurance agent verifies the integrated whole. Small sequential work remains one loop, and specialist workers cannot recursively create an unbounded workforce.

A bounded executive cell can sit above the harness. CEO, COO, and Marketing run as distinct fresh-context agents rather than one conversation changing hats. Marketing returns independent evidence, CEO owns strategic synthesis, and COO turns charter-authorized direction into harness jobs and follows their flow. An accepted standing autonomy charter defines their goals, scopes, budgets, initiative ceilings, gates, and stop conditions. Hermes may then activate eligible internal runs without requiring a fresh prompt each time; OB1/OpenBrain carries typed decisions, work state, outcomes, and friction between contexts. Consequential actions remain gated.

This remains an instruction harness, not yet a durable software-factory runtime. Persistent jobs, queues, worker isolation, artifact lineage, recovery, or control-plane infrastructure must be earned by one proven repeated workflow and measured against simpler primitives.

Use `exponential-strategy` when a product, workflow, or organization may have a real compounding learning, decision-context, ecosystem, or coordination mechanism. It implements the current OpenExO 3.0 model as a conditional lens: intent first, then an evidence-backed leverage test, one or two relevant DRIVE/SHAPE constraints, the smallest workflow-level Intelligence Loop, and a proportional REWRITE proof only when warranted. It explicitly keeps ordinary features out of MTP and 10x theater, preserves hard-coded automation where rules are stable, and treats book chat as exploratory rather than canonical.

The steward uses a compact intent-and-situation kernel before architecture and reclassifies when code, tests, review, strategy evidence, or new user input crosses a risk or system boundary. `root-cause-debugging` prevents speculative fixes, `intent-aligned-review` checks whether the right thing was built before code quality, and `evidence-before-completion` limits final claims to fresh, proportionate proof.

Use `audience-boundary` whenever internal instructions, private reasoning, audit state, developer notes, secrets, simulation markers, or implementation metadata could reach a UI, API payload, email, notification, export, metadata field, or generated artifact. It establishes an explicit audience contract, removes internal fields before serialization, and verifies the actual network and render surfaces. It complements copy cleanup: brand truth and audience separation come first, optional marketing or technical-writing specialists come next, and `ai-writing-audit` or an explicitly requested humanizer runs last.

External writing packs are optional specialists, not a new default stack. Humanizer is useful for context-aware prose cleanup, Stop Slop is a stricter opt-in stress test, Agent Style belongs on technical prose rather than marketing, and MarketingSkills should be routed to one relevant capability at a time. Approved project voice, factual claims, current product stage, and the audience contract outrank generic token bans.

The copy system treats every new user-visible string as product work. `brand-copy-steward` reads existing product and brand truth, builds missing marketing context only when needed, separates public copy from review and implementation notes, and applies focused editorial sweeps. It adapts selected product-context and editing ideas from MarketingSkills rather than importing the full repository.

The `100-year-copywriting-engine` remains the suite's specialist for direct response, offers, campaigns, headlines, sales pages, emails, and original advertising concepts. Its Ken Moskowitz framework library is preserved, but the engine now chooses buyer strategy before framework, uses voice behaviors instead of automatically imitating named writers, removes unsupported performance percentages, and emits a clean public-copy package. Ordinary product UI routes through `brand-copy-steward` instead.

`ai-writing-audit` incorporates Humanizer's useful no-fabrication, voice-sample, and second-audit behaviors while preserving the suite's context-aware rule: flag the effect, not a single token. The suite records pinned upstream research refs and licenses under `third_party/`.

Validate the complete suite after changing skills or metadata:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\validate-skill-suite.ps1
```

The validator checks the plugin manifest, every skill's frontmatter, skill-name alignment, local Markdown references, UI prompt metadata, unresolved placeholders, and Git whitespace errors.

## Updating Installed Skills

Codex loads installed skills from `C:\Users\<you>\.codex\skills` at startup. Restart Codex after a sync.

From the repository root:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\update-installed-skills.ps1
```

The updater:

- pulls with `git pull --ff-only` and stops on a nonzero native exit;
- validates skill frontmatter before changing the installed suite;
- tracks the fingerprint of the last synced version;
- refuses to overwrite local installed drift by default;
- stages replacements before swapping them into place;
- backs up every replaced installed skill;
- reports add, update, unchanged, and conflict states.

For a local source checkout without pulling:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\update-installed-skills.ps1 -NoPull
```

For the first managed sync, or after intentionally promoting installed changes back into the source repository, use:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\update-installed-skills.ps1 -NoPull -Force
```

`-Force` is an explicit replacement decision. Existing installed skill folders are backed up before replacement.

Preview actions without pulling or writing:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\update-installed-skills.ps1 -NoPull -DryRun
```

## Personal Auto-Update

The optional logon updater is safe after one managed sync establishes the fingerprint state:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\install-auto-update.ps1
```

It will stop rather than overwrite if installed skill files were edited outside the source repository. Promote intended local changes into the source, validate them, and run a managed sync before restoring unattended updates.

Remove the hook with:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\uninstall-auto-update.ps1
```
