# OpenExO Model Version Guard

## Canonical Working Version

This skill is based on the official OpenExO model and living book available on 2026-08-14:

- [ExO Model 3.0](https://openexo.com/exo-model-3)
- [The Organizational Singularity, v25, June 2026](https://openexo.com/organizational-singularity)
- [OpenExO Resource Hub](https://openexo.com/resource-hub)

The Resource Hub also listed an official "ExO 3.0 Codex Skill" during this research pass, but its content required login. This local skill does not copy or claim to reproduce that locked package; it is an independent Agentic Software adaptation of the public official model and living book.

The official hierarchy is:

1. **ExO 3.0** is the destination architecture: MTP + DRIVE + SHAPE.
2. **The Intelligence Stack** is the operating model: PURPOSE, SENSE, INTERPRET, DECIDE, ORCHESTRATE/ACT, and LEARN, with GOVERN/ASSURE across the loop.
3. **REWRITE** is the migration playbook: BACKCAST & DEFINE, ASSESS & PREPARE, EXTRACT, DIAGNOSE & STRIP, BUILD & PROVE, and REWIRE & EVOLVE.

### MTP As Protocol

The current model treats Massive Transformative Purpose as three operational layers:

- Human direction or identity.
- Hard constraints agents and people may not violate.
- Weighted priorities for bounded tradeoffs.

In this suite, the existing intent contract remains the authority for the immediate build. An MTP can add durable strategic context; it cannot erase a specific prohibited outcome, user authority boundary, or safety rule.

## Relationship To ExO 2.0

ExO 2.0 uses MTP + SCALE + IDEAS. The 2026 living book says ExO 3.0 preserves MTP and replaces the SCALE/IDEAS split with DRIVE and SHAPE because its model no longer treats the internal/external firm boundary as the primary organizing distinction.

Use SCALE/IDEAS when:

- The user explicitly asks for the 2.0 model.
- Comparing historical framework versions.
- A named legacy artifact or assessment depends on it.

Do not present SCALE/IDEAS as the current ExO 3.0 model.

## Chat And Secondary-Source Rule

The public OpenExO AI-X chat can help generate questions and contextual explanations, but it is not canonical. During the 2026-08-14 research pass for this skill, a chat answer labeled as ExO 3.0 expanded DRIVE and SHAPE differently from the official 3.0 model page and living book.

Therefore:

1. Cross-check named concepts against the official current model or book.
2. Prefer dated, versioned official material over undated chat output.
3. Mark forecasts, illustrative ratios, and vendor examples as claims from the source rather than settled engineering facts.
4. Independently verify current legal, security, and technical claims before relying on them for a high-stakes implementation.

## Translation Into Agentic Software

Use the framework as a set of questions, not as mandatory infrastructure:

| OpenExO concept | Agentic Software translation |
|---|---|
| MTP / Purpose Control | Durable purpose, prohibited outcomes, and priority policy above the immediate intent contract |
| Decision Architecture | Method, authority, reversibility, threshold, and escalation for every decision type |
| Recursive Learning | Versioned workflow corrections, eval cases, measured outcomes, and controlled promotion |
| Intelligence Stack | A workflow-level PURPOSE-to-LEARN loop; services only when proven necessary |
| Value Moat | Compounding proprietary context, decision traces, user/participant effects, reuse, or curatorial judgment |
| Elastic Agency | Capability and authority assigned by evidence across humans, tools, models, and agents |
| Safe Autonomy | Scoped permissions, evals, logs, rollback, kill paths, and named human accountability |
| Human Architecture | Preserve human judgment, relationships, ethics, taste, learning paths, and transition consequences |
| Adaptive Architecture | Swappable modules and models with bounded interfaces and recovery paths |
| Ecosystem Trust | Scoped APIs, identity, provenance, auditability, and explicit liability/authority boundaries |
| REWRITE | Intent-first, evidence-backed replacement of one workflow before broader migration |
